## Implemented boundary

The Debug learned-comparison button now fits the saved run's frozen profile
once and generates a pair: retained legacy hypotheses and an ink-only lossless
grouping proposal explicitly marked unresolved. Selective prediction returns
before query-group or whole-chord encoding. Complete learned reads are nil and
ranks empty; optional personal weights cannot resolve ownership. Original
source-index coverage does not establish a correct symbol boundary.

Both arms keep the same scored attempts. Unresolved complete fresh inputs stay
no-reads; unsupported inputs are counted separately. Capture-grouping issues
retain selective proposals but remain their original scoring exclusion. Known
unsupported input is correctly excluded in paired receipts only; historical
standalone report output stays unchanged.

Pair validation binds source/evaluation digests, run, model, frozen profile,
lessons, row IDs/order and pair ID. It reconstructs eligible rows and checks
actual unsupported/unresolved counts. One append-only JSON publishes both arms
through exclusive filesystem linking. A profile-store lock transaction includes
the matching-enabled-profile check, pair save and UI publication; its closure
does not reenter or mutate that store. Opt-out, stale results and save failure
publish neither arm. No render, acceptance, teaching or erasure action was added.

The view retains original hypotheses and adds a finite display-only preview
from exact `recognitionStrokes`, colored by unverified proposed source groups.
It explicitly says zero resolved reads is not recognition improvement.
