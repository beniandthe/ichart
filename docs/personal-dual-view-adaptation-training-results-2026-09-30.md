fit, blind prediction, score and independent reconciliation. The candidate
passes three of four conditions but fails the untaught-recognition guard.
It is not eligible for the next independent-writer gate or app integration.

## What actually changed and ran

Implemented `personal_dual_view_adaptation.py` and eleven focused tests; existing
encoder, differentiable solver, NumPy residual and Swift residual sources are
unchanged. The [frozen protocol](personal-dual-view-adaptation-training-protocol-2026-09-30.md)
declares one generic continuation control and one adaptation-aware candidate.

Both start from identical final dual weights, train only on the same 32 public
training writers, and use ten final-only epochs, seed 29, four CPU threads,
AdamW 0.0001, weight decay 0.0001 and cosine schedule. BatchNorm running buffers
remain exactly the original parent's. Each arm executes 640 identical directed
writer/session episodes and 62,060 outer query rows; twenty exact copy queries
per arm are excluded from the loss. Across 10,240 support selections, 55 labels
appear 106 times and 42 appear 105 times. All 97 classes compete throughout.

The candidate optimizes equal-weight generic query cross-entropy and query loss
backpropagated through the exact fixed lambda-0.1 residual learner. The control
uses generic query cross-entropy for both halves. This tests training the
representation for the existing learner, not a different OCR engine or a rule
based on the user's accepted handwriting.

The mechanism is motivated by [R2-D2's differentiable closed-form learner](https://arxiv.org/abs/1805.08136).
That paper supports the training approach, not chord accuracy or success here.
Adjusted scores are ranking values; this experiment does not calibrate trust.
