## Hypothesis and limits

The completed m/9 intervention suppressed an existing class's learned
correction because it refitted every column over the expanded support matrix.
This successor copies every untouched correction column and refits only labels
explicitly present in appended lessons. It is a general update rule, not a
chord, writer, threshold or query-answer exception.

Ridge remains the existing class-balanced residual objective, lambda 0.1. Its
standard multi-output formulation is described in the
[scikit-learn documentation](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html).
The column-preserving update is an experimental policy here, not a published
recognition-quality guarantee. An updated column can overtake an unchanged
correct column; the synthetic counterexample is a required invariant test.

The original residual implementation, model weights, old m/9 evidence and
private profiles remain unchanged. Do not replay the labeled private queries
as fresh evidence or fit to them. No new participant is recruited.

## One fixed update and four arms per encoder

For each writer, retain the complete `core10` support array in its original
recorded order, including original label/ID/vector/source bindings. Its explicit
label set is `A B C D E F G b - 7`.

Append only that writer's `catalog21` lessons for labels absent from core10,
sorted by exact label: `( ) 1 2 3 4 5 6 9 m o`. These are all domain-permitted.
Join each lesson's example ID to its original stored packet/raster/source row,
and bind the exact bytes. Do not replace the prefix with the separately ordered
catalog profile; do not treat encoded-array equality as original-ink provenance.

All arms use the same raw 97-column generic scores, 128-dimensional unit
embeddings, explicit support, regularization, and source schedule:

1. Generic frozen scores, no personal fit.
2. Reference: unchanged full residual fit on the ten prefix lessons.
3. Full-refit diagnostic control: unchanged residual fit on the assembled 21.
4. Class-frozen candidate: same full solve on the assembled 21, but copy all
   86 untouched correction columns exactly from the reference and replace only
   the 11 appended-label columns.

No softmax/renormalization, calibrated-confidence claim, rank rescue, answer
lookup, threshold or parser selection. Score in fixed per-column feature order
so vocabulary growth cannot perturb untouched score arithmetic. Rank by raw
score descending, then exact label ascending. If the actual winner is outside
the exported domain, the reader result is unresolved; never promote a runner-up.

Snapshot validation must reject edited/deleted/reordered old arrays or source
commitments, duplicate IDs, encoder changes, malformed features/scores, invalid
vocabulary suffixes, or nonzero non-encoder padding. Novel labels are supported
synthetically but this fixed public screen adds no encoder-vocabulary columns.

## Predeclared disposition

Every condition must hold in BOTH encoder views and BOTH raw/no-copy views:

- All 86 untouched weights and scores are bit-identical for every valid query;
  invalid inputs remain recorded as unresolved rather than excluded.
- Added-label net correction is strictly positive versus the reference.
- Overall domain net correction is strictly positive versus the reference.
- Zero correct-to-wrong or correct-to-unresolved harms on old and remaining
  untaught domain labels.
- No writer has a negative candidate/reference domain net correction.
- Zero newly introduced domain outputs on out-of-domain queries where the
  reference was unresolved.

The full-refit control is diagnostic only, not an alternate winning arm. Any
failed condition rejects this fixed candidate for app integration. Preserve all
results; do not change the sampler, catalog, lambda, scoring, encoder, domain,
gates or queries after results. A pass licenses only separate Swift-runtime
parity and fresh handwriting gates in both chart styles, never live activation,
shipping, or a claim of user-agnostic chord recognition.
